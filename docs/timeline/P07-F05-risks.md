# P07-F05 risk controls

Conservative risk C for derived clinical display. Local synthetic engineering is authorized; formal prerequisite and qualified clinical/privacy/architecture/licensing signoffs remain pending. Production clinical functionality stays disabled.

- False reassurance: health reauthorizes actual canonical source and coverage; source failure is unavailable, not empty/healthy. Counts are coverage-scoped. Exact cache bytes/hash gate and recording-time conflict checks withhold suspect materialized facts. Health timestamps/lag are operational, not clinical onset or live-feed promises.
- Clock ambiguity: unknown/future outstanding times yield unknown lag; backwards recording timestamps alert and block preview. Equal recording timestamps and backdated clinical times are valid. Five-minute target is local simulation scope. Accelerated clinical fixture time is isolated from Kafka's real transport/retention clocks.
- Lost deliveries: source and outbox commit atomically; publication never clears queue. Acknowledged opaque pointers are reauthorized against source. Local SQL commit precedes offset commit; failure retains offset, duplicate delivery is idempotent. No distributed exactly-once claim.
- Cross-patient leakage: hashed patient/record stream keys, pointer-only payload, exact canonical membership/hash, per-delivery live Foundation/local authority and source-kind permissions. No source values/session credentials in messages or routine logs. Strict size/contract/local endpoint bounds. Wrong context stops without offset commit.
- Poison/backlog: predecessor validation stops unsafe out-of-order delivery. Existing quarantined/invalid queue pointers cannot be acknowledged as applied. Restore authority/source before retry; derived rebuild cannot repair authoritative corruption. Bounded 50-item passes and no implicit command replay.
- Monitoring limits: current health view is not a durable incident history or external paging integration. Broker uptime is explicitly not observed by the dashboard. Normal dashboard observation performs reads only and stops on offline/error/context invalidation; reconnect requires explicit refresh.
- Deployment limits: single local broker/plaintext/24-hour transport retention do not establish approved clinical SLO, availability, security or retention. Production configuration requires qualified decisions; this adapter is restricted to loopback simulation.
- Regression/data loss: preserve original rows/evidence/config hashes; use disposable source fixtures and unique topics for disruptive broker tests. No production clinical/source migration or cleanup deletes. CI job is configured but remote execution is not claimed.
