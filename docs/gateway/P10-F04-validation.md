# P10-F04 Cost and runtime resilience

In the local synthetic workspace, gateway operators need bounded provider attempts and a clear manual fallback when a provider is unavailable. The gateway may process only the approved synthetic workflow under the existing policy and release checks. Clinical generation and hosted connectivity require their existing approvals.

Use the existing tenant token cap, charging estimated input units for each dispatch, including unsuccessful dispatches. A trace and dispatch ordinal identify the charge. Persist charges and breaker state with the existing attempt and receipt transaction. The breaker is scoped to tenant, provider and model version. Three consecutive transport failures open it for 30 seconds. After cooldown a serialized request probes the route. A valid transport response closes it, even if the output fails schema validation.

Allow one retry for a transport failure when budget and the breaker permit it. Give each transport call a 500 ms deadline. Synchronous adapters must enforce the supplied deadline in their transport and the gateway discards late returns. Arbitrary blocking callbacks cannot be interrupted by the synchronous API. Disable shared output caching and reuse only the existing scoped idempotency receipt, subject to policy and release rechecks. Use manual review with no generated output on timeout, outage, open circuit or exhausted quota.

Schema 61 adds a dispatch ledger and breaker table. They store scope and accounting metadata without input or output text. A local rollback can restore a pre-migration database backup with its matching application build. The operator can disable dispatch through the release alias while preserving accounting history.

The attempt trace joins to `gateway_dispatch_units` for the charged units and transport result of each call. The usage total includes charges made before schema 61. Transport results are separate from the final output validation outcome. On an outage, record the trace and continue with manual review. The next eligible request can probe the route after cooldown. Use a new submission key for an intentional new attempt. Reusing a key returns its previous outcome and never charges a second time. A storage failure rolls back the attempt, ledger, budget, and receipt together. A remote provider that can independently bill after a storage failure requires a separate reconciliation design before hosted use.
