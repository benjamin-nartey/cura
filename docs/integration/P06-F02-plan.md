# P06-F02 — Local SMART-style authorization and scopes

Authority: product-owner continuation after verified P06-F01; local synthetic engineering only. Formal phase acceptance and production clinical activation remain unchanged.

Inventory: existing Foundation sessions supply verified actor/facility/purpose; SQLite identity bindings and authorization policy supply current account and role checks. F01 owns persisted source reads and canonical mappings. Existing legacy FHIR endpoints use workspace cookies; mobile uses Foundation bearer sessions. Neither is an app-scoped SMART grant. Reuse their identity/purpose/read gates; do not reinterpret workspace session tokens as SMART tokens.

Implement a bounded standalone public-client authorization-code/PKCE-S256 flow, following SMART App Launch 2.2 scope syntax. Support launch/patient plus explicit patient/{supported-type}.r only. Do not advertise search, writes, wildcard/user/system scopes, refresh/offline access, OIDC identity tokens, EHR launch or certification. Discovery describes only implemented capabilities. Registered redirects are exact HTTP(S) URLs: the trusted built-in callback or an isolated reserved smart-client.localhost hostname on a separate port. The workspace cannot serve client hostnames; only local synthetic apps are allowed. Audience is a configured loopback FHIR base, never derived from an untrusted Host header.

Schema 49 adds tenant-owned clients, pending authorization requests, grants, single-use hashed codes and hashed opaque access tokens. Registration retries use immutable request hashes/keys. Clients have versioned disable, grants have owner/admin revoke. Request approval is bound to current user/session/facility/purpose, nonce and expiration. Codes live 60 seconds, grants/tokens at most five minutes. Code replay revokes the associated grant; revocation must commit even when exchange fails. Token secrets/verifiers are not stored or audited. No clinical tables or source commands change. Expired security metadata is retained locally for audit; no new destructive retention job is introduced.

App reads require a SMART bearer token (no cookie fallback), live original identity session, exact client/audience/patient/facility/purpose, current account/membership/permissions and actual source-record authorization. Clinical purpose is TREATMENT only; organization administrators register clients but cannot grant themselves clinical scopes. Scope failure must occur before clinical record lookup. No resource search or mutation endpoint is introduced. Local read-by-ID resolution is bounded; exceeding the bound returns an error, never incomplete success.

Privacy boundary: delegated responses omit the proprietary source-context extension and its profile assertion; they remain base R4 resources. Internal transport correlation values must not be exported through F01's provenance either, since some historical source rows used a session identifier as correlation metadata. Preserve those stored rows; explicitly exclude transport-only secrets from the exported clinical fact contract. No clinical information is removed. Add regression oracles for absence of session IDs/internal source context in delegated output.

UI: administrator client registration/disable; clinician app authorization with actual patient selection, exact scopes, allow/deny; current grant review/revoke; first-party local simulation app demonstrating real redirect, browser-bound state, PKCE exchange, bearer read, failure diagnostics and memory-only token storage. Empty/loading/denial/stale/expired/network/cancellation states must be truthful. Cross-origin OAuth/resource access is restricted to registered loopback client origins, without credentials; workspace management uses same-origin cookies and explicit form nonce where authorization is consequential.

Evidence: real SQLite persistence/migration/reopen/rollback tests; PKCE mismatch, code replay/concurrent exchange, expiry/revoke, insufficient scope, wrong patient/tenant/facility/purpose, disabled client/user, identity/dependency outage and recovery, nonce/state/audience/redirect attacks, privacy/audit redaction, browser happy/denied/revoked scenarios and accessibility/responsiveness. Run current domain regression, relevant browser regression, lint/types/build, governance and official FHIR validator after the provenance boundary correction. Configure CI without claiming an unexecuted remote run.

Primary references: https://hl7.org/fhir/smart-app-launch/STU2.2/app-launch.html and https://hl7.org/fhir/smart-app-launch/STU2.2/scopes-and-launch-context.html. This is a restricted local SMART-style subset, not a full SMART conformance claim or external sharing/clinical release authorization. F03 imports/webhooks remain out of scope.

Cold-start completion: an unauthenticated authorization request retains its original URL while sign-in/MFA occurs in a separate tab; explicit continuation revalidates the original request before patient approval. No login route, MFA requirement or arbitrary return redirect is changed.
