# P06-F01 — Canonical FHIR R4 profiles

Authority: clarified local simulation implementation in docs/governance/SIMULATION-IMPLEMENTATION-AUTHORITY-2026-11-03.md. Formal acceptance is not inferred; missing production reviews do not block this engineering scope.

Inventory: packages/domain/src/fhir-map.ts and fhir.ts serve a legacy chart projection and lightweight structural checks. packages/fhir currently contains a profile-location pin only. New clinical-source/work/scheduling records from P04–P05 are not represented by those legacy transformations. Existing FHIR endpoints and evidence must remain functional. The old ADR's absence of a JDK is obsolete: Java 21 is now installed locally.

Scope: extend the existing integration bounded context with versioned CuraSphere R4 source profiles and explicit forward/reverse transformations for current Patient, Encounter, Condition, Observation (quantity/components), ServiceRequest and MedicationRequest facts, plus allergy compatibility where appropriate. All transformations are synthetic preview/validation before any import mutation. Preserve original source identity/version, coded tuple/unit metadata, null/unknown distinctions and workflow safety state. Never turn a non-executable draft or untransmitted request into an executable clinical order. Unsupported/inconsistent inbound semantics must produce actionable diagnostics rather than silently dropping data.

Risk class C conservative engineering classification. Required controls: actual source-record permissions/tenant/patient context before export preview; immutable source provenance; mapping-version pin; no clinical side effects from reverse preview; strict unsupported-field/extension diagnostics; local sandbox/dependency gates; PHI-safe audit and bounded JSON; no external transmission. Use actual persisted source records in the UI/API and clearly state mapping scope and simulation limitations.

Validation: HL7 FHIR R4 profiles/StructureDefinitions and an independently executed official validator, not merely assertions about hand-written field checks. Investigate pinned validator 7.0.4 (official GitHub release, SHA-256 43e29fa8822d670740a909c395ca5b70a3d07fbaa8936f8dedc6a98b007f555b). Configure terminology validation/network behavior explicitly; no patient resource may be sent to an external validator service. Official R4 profiles/base packages may be downloaded as engineering dependencies. Do not describe offline structural/profile checks as licensed terminology validation.

Evidence needed before completion: real persistence/API and role-appropriate mapping preview, versioned round-trip oracles for all supported resource kinds with no silent loss, official validator output including negative cases, scope/permission/error/security tests, restart/failure behavior, full regression/build/type/lint, conformance contracts/ADR/runbook, and an experimental feature register with observed results. Existing governance records remain unchanged. F02 SMART authorization must not be represented as implemented by F01.

Primary technical references: https://hl7.org/fhir/R4/profiling.html, https://hl7.org/fhir/R4/validation.html and https://hl7.org/fhir/R4/servicerequest.html. FHIR validity and local profile correctness are engineering checks, not clinical/regulatory approval.

Implementation decision (2026-11-03): use an additive, read-only `/api/integrations/r4/preview` contract and `/interop/source` workbench, leaving legacy endpoints unchanged. Database facts remain authoritative; no migration or duplicate clinical storage is needed. The versioned source-context extension retains original namespaces, nulls, source statuses and provenance not expressible in base R4. Inverse mapping reads the actual R4 clinical fields, restores source-only context, and rejects any field that cannot be reproduced exactly. This is a bounded CuraSphere profile codec, not a general partner importer. Reverse preview requires an exact current source-context match after fresh source authorization; stale context returns 409. Supported edits are reported as proposed field differences and never applied. External imports, delivery, consented external sharing and SMART remain separate features. Internal treatment previews use existing patient/source read permissions; they do not grant sharing or research access.

Profile IDs are stable SHA-256 values of tenant + resource type + internal ID, preventing invalid underscore IDs and cross-tenant reference collisions. Legacy non-URI coding namespaces are represented as explicit CuraSphere URNs, never relabeled as licensed standard codes. Medication drafts and untransmitted service requests remain proposals. Source metadata is immutable within a reverse preview, and unsupported clinical semantics fail closed. Audit stores source IDs/outcomes and counts only, never resource JSON or clinical values. Metrics derive from audit counts rather than new mutable clinical state.
