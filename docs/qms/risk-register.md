# Risk register — foundation slice

| Id | Hazard or threat | Harm | Mitigation in this slice | Residual | Status |
| --- | --- | --- | --- | --- | --- |
| R1 | Cross-tenant disclosure | Privacy | Session-derived organization and facility on every query. Negative tests. | Dev server is unauthenticated beyond the directory picker. | Open, accepted locally |
| R2 | Threshold read as a diagnosis | Clinical | Wording, no orders, no model text | A reader can still over-interpret a High flag | Open |
| R3 | Duplicate or lost double-submit | Record integrity | Idempotency key in the same transaction | A refreshed form mints a new key | Open, accepted |
| R4 | Stale encounter completion | Record integrity | Encounter version | User must reload | Open, accepted |
| R5 | Audit edited on disk | Accountability | None beyond file permissions | No tamper-evident log yet | Open |
| R6 | Real PHI typed into the dev database | Privacy | Banner, runbook prohibition | Depends on the operator | Open |
| R7 | Assistant invented fact | Clinical | No assistant in this slice | Appears when a later phase adds a model | Watching |
| R8 | Subscription endpoint calls an arbitrary host | Privacy, availability | Only the local inbox is accepted | No outbound integration until an allowlist exists | Open, accepted locally |
| R9 | Export read as a frozen legal extract | Record integrity | The job records who asked; the file is built from source rows at read time | A later chart write appears in a later download of the same job | Open, accepted locally |
| R10 | Stale patient state read as the chart | Clinical | The build time and a stale line are shown. The chart stays on the page | A reader can still ignore the line | Open |
| R11 | Derived sentence kept after its source changes | Clinical | The claim stores a source hash. A mismatch sets the state to invalidated | The old sentence remains visible with that state | Open |
| R12 | A model answer enters the chart | Clinical | The gateway refuses clinical prompts, stores no failed output, and does not file evidence | A later phase could allowlist a model | Open |
| R13 | An agent tool writes or calls a model on its own | Clinical | Tools must be on the manifest. Draft tools do not execute. Model tools go through the gateway, which refuses. A second person approves the parked review | A later manifest could allow a write | Open |
| R14 | An unsupported sentence is shown as the summary | Clinical | The grounding threshold is 1. Invalidated claims are flagged and the summary is withheld. Treatment wording stores no answer | A reader can still open the evidence card and the source row | Open |
| R15 | A draft is mistaken for a signed note | Clinical | Draft and accepted states look different. The row cannot be signed. Acceptance does not change the chart. Audio produces no transcript | A reader can still treat the draft text as an order | Open |
| R16 | A critical threshold or a model sentence is treated as a cleared alert | Clinical | The critical pin is labeled as local configuration. The gateway refuses the explanation. Acknowledgement does not set the flag to none | The pin can be wrong for real care. This database is synthetic only | Open |
| R17 | A local interaction pin or a model sentence is treated as a cleared medication warning | Clinical | The rule id, version, and source are stored on the warning. A high-risk warning blocks the medication-list write until acknowledgement. The gateway refuses an explanation | The pin is not a drug-knowledge database. This database is synthetic only | Open |
| R18 | An outreach line is treated as a message the patient received | Clinical, privacy | Consent and channel are required. The body is a stored template. Failure opens an escalation task and does not create a message. There is no outbound transport | A reader can still treat the stored sentence as contact that happened | Open |
| R19 | A patient explanation or a quiet assistant is treated as clearance to stay home | Clinical, privacy | Urgent phrases store a fixed instruction to call emergency services. Result sentences say they are not a diagnosis. Model output is ignored. The patient session cannot open the clinician chart | A person can still delay care. This database is synthetic only | Open |
| R20 | A facility count is treated as a live census or a forecast | Clinical, operations | Each signal names its source table and a freshness mark. Empty sources stay not current. Capacity is the open share of stored beds. The gateway cannot replace the sentence | A reader can still treat a fresh count as the whole hospital. This database is synthetic only | Open |
| R21 | A stored comparison is treated as a forecast, a staffing order, or a business result | Operations | Factors and confidence `none`, `low`, or `stored` are on each sentence. Empty inventory is not forecast. A hold does not change the sentence. The KPI delta counts stored rows and says it is not a revenue or clinical outcome. The gateway cannot replace the sentence | A reader can still treat the comparison as a plan. This database is synthetic only | Open |
| R22 | An analytics export is treated as a patient list or an identified report | Privacy | Only an auditor can read the mart. Ingest keeps a facility id and drops other payload fields. Cells below 5 are suppressed. The body is scanned for a name, MRN, or birth date before release. Lineage stays on the export row | A person with the database file can join an outbox id back to the original payload. This database is synthetic only | Open |
| R23 | A population count is treated as a case list, an outbreak, or a legal clearance | Privacy, clinical | The minimum is 5, and a remainder that would reveal a smaller group hides the total. Missing and restricted jurisdiction tags withhold every count. Vaccination and map sentences say those sources are absent. The body is scanned for a name, MRN, or birth date | The jurisdiction tag is local configuration, not a statute. A reader can still treat a released count as a diagnosis. This database is synthetic only | Open |
| R24 | A research workspace is treated as an ethics approval or a patient-level extract | Privacy | The ethics status stays not-reviewed. Dataset versions are inserted and not updated. The requester cannot approve an export. The payload is the population count snapshot, refused when that build is withheld or contains a direct identifier | A reader can still treat the protocol label as an approval. This database is synthetic only | Open |
| R25 | Study metadata is treated as a DICOM image or a diagnostic read | Clinical, privacy | No pixel payload is accepted. The page states that no DICOMweb endpoint and no viewer are connected. A release omits patient, accession, and description. The gateway refuses interpretation | A reader can still treat a modality and a typed report as a completed image read. This database is synthetic only | Open |
| R26 | A typed device reading is treated as a live alarm or a page | Clinical | Connectivity stays not-connected. The same time and value does not open another mark. An older time is out-of-order and opens no mark. The fourth open crossing stores an escalation sentence. No page is sent | A reader can still treat the threshold mark as a monitor alarm. This database is synthetic only | Open |
| R27 | A recorded amount is treated as a bill, a collected payment, or a payer decision | Financial, privacy | Invoices and payments stay recorded. Eligibility stays not-checked. Claims stay drafts. The subscription stays not-billed. The ledger does not return problems or results. The gateway cannot change a cent | A reader can still treat the recorded cents as money collected. This database is synthetic only | Open |
| R28 | A passed refusal suite or a signed hold is treated as a promoted clinical model | Clinical | The suite expects refused. A second auditor can sign only a hold. A promotion attempt stays not-promoted. The model row stays disabled. Subgroup and drift sentences say those measures are not calculated | A reader can still treat a passed suite as permission to generate clinical text. This database is synthetic only | Open |
| R29 | A local pin or a local read is treated as a second region, a failover, or single sign-on | Operations, privacy | Residency accepts only local-sqlite. Federation stays not-connected. Keys stay not-configured. A drill records failover as not-run. moveTenant is refused | A reader can still treat the pin as a cloud region. This database is synthetic only | Open |
| R30 | A reviewed listing or a compatibility sentence is treated as a running extension, an OAuth client, or a paid share | Privacy, clinical | Scope stays health.read. Risk stays administrative. Review is a hold by a different role. Release, OAuth, and sandbox creation are refused. A share stays not-billed. Stop does not signal a process | A reader can still treat the listing as an installed app. This database is synthetic only | Open |
| R31 | A dossier, a refused check, or a release attempt is treated as regulatory clearance or a promoted model | Clinical | The strategy stays not-approved. The risk file stays unsigned. Verification is stored only as refused. Clinical evaluation stays not-performed. Surveillance stays not-active. A different auditor can record only not-released. The refusal gate stays disabled | A reader can still treat the dossier as clearance to generate clinical text. This database is synthetic only | Open |
| R32 | One module card, or a refused check, is treated as clearance for imaging, ECG, pathology, dermatology, maternal, cardio, and oncology together | Clinical | Each module has its own intended use and model card. Validation is a gateway refusal by a different auditor. Studies stay not-run. Performance stays not-calculated. A platform approval is refused | A reader can still treat one not-cleared card as a diagnostic device. This database is synthetic only | Open |
| R33 | A foundation session or chart list on PostgreSQL is treated as proof that the chart has left SQLite | Operations | Workforce sign-in, the patient list, encounters, appointments, problems, allergies, medications, and results use PostgreSQL. The same ids are stored in SQLite so the timeline can join them. Lab orders stay in SQLite. A lab result still writes its observation only in SQLite. Kafka and Temporal are not running | A reader can still treat one list as the whole chart | Open |

Review before any phase that calls a model or imports real data.
