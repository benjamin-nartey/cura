# P08-F05 architecture, contract and operations

Local synthetic clinician inspection, contract version 1. Formal Phase 08 NOT_STARTED; qualified reviews pending. No migration: schema 57 and existing immutable clinical/work ledgers, Twin builds and timeline snapshots remain authoritative for this derived view. No new queue, source edit or deletion. ADR 0085 records the chosen design.

## Read contract

GET /api/patient-twin/inspection?patient={id} uses the existing same-origin live-session boundary. GET /api/mobile-workspace/twin?patient={id} uses the existing explicit mobile origin and live bearer session; cookies never substitute. Both call readTwinInspection. Responses are no-store. Unknown/duplicate arguments, invalid identifiers and incompatible modes fail validation. Invalid request is 422, source/build/session conflict 409, unavailable authority/integrity 503; unauthorized/forbidden/not-found retain existing boundary semantics.

Optional view is facts (default), baselines, compare, evidence or history. Facts accepts category all/problems/allergies/medications/observations/pending, literal query up to 80 characters and limit 1..20 (default 10). Subsequent pages require build, source and signed cursor. Other views require exact build/source; evidence requires fact ID, history canonical event ID, comparison baseline last-visit or retained snapshot ID and optional signed cursor. There are no write methods on this adapter. Existing explicit snapshot/rebuild/review/job commands remain under their original APIs and Source tools.

Version 1 response contains patientId and minimal currently authorized identity, status, checkedAt, sourceHash, build/coverage metadata, filters, overview or null, facts/total/next, reviewSourceIds, baselines, comparison/comparisonFacts and evidence. Noncurrent state returns no clinical overview, assertions, comparison or evidence. Comparison values are verified exact ledger snapshots keyed by authorized canonical event IDs; current fact IDs and canonical event IDs are distinct. Clinical comparison excludes work; pending work remains separately labeled. No prior completed visit makes no absence claim. Draft medication counts are proposals, never active therapy; risk and care gaps remain unassessed.

Facts and comparison cursors use domain-separated HMAC-SHA256, binding organization/facility/user/purpose/session digest/patient/coverage/build/full clinical-and-work source hash/filters/limit/baseline. Source changes invalidate pages, including work-only changes during clinical comparison. Current evidence delegates F02 exact source inspection; historical evidence delegates canonical source inspection. Every call reproduces source authorization, availability and integrity before returning values. Structured audit records action/resource/outcome without source payloads. Errors return generic messages. Existing source and identity audit/trace plumbing is reused.

## UX and recovery

/patients/{id}/twin presents current source counts, searchable bounded assertions, pending items, exact evidence and side-by-side comparison. /twin/sources retains all F01-F04 capture/rebuild/conflict/operations controls. Both server pages check current source access independently of the derived cache, allowing authorized repair of corrupt cache. No patient-specific identity is emitted in the generic server shell; the client receives identity only with the source-gated DTO. Web evidence uses native dialog with title focus, Tab containment, Escape and trigger focus restoration. UTC source/clinical/check/processing times remain distinct.

React Native Workspace opens the same read contract through the mobile adapter. Tokens remain in memory, never source links/storage; native backgrounding, browser offline/reconnect, patient/session/base changes, cancelled/late reads and failed access clear values. Native source-tool links carry no bearer token. Twin reads have an explicit 30-second transport bound for source/history reproduction, with visible cancellation and epoch-based late-response rejection; other mobile endpoints retain their 12-second bound. This is an interactive transport limit, not a production latency SLO. Existing patient directory is reloaded after leaving inspection. Parent request failures also check the originating token and navigation generation, so a late failure cannot clear a newer context. No command replay or offline clinical store is added. Web serializes independent GETs with the existing Twin read scheduler and aborts obsolete reads; operation epochs reject late responses.

If values are withheld: restore Foundation/source access first, explicitly refresh, then use Source tools for authorized rebuild/repair. Changed source requires restarting pagination/comparison; do not reuse a cursor. A failed exact-evidence read clears cached inspection. Bounded local read limits are safety controls, not production capacity certification. Monitor existing HTTP errors/latency and twin.inspection audit outcomes; no new metrics service or claims of validated clinical freshness. Escalate repeated 503 to source/identity/integrity investigation without logging patient payloads.

## Rollback and limits

Disable the new navigation or revert only F05 UI/read adapter changes to restore prior Source tools as the primary view. No database downgrade or source deletion is needed. Retain new snapshots/builds and audit evidence under existing retention rules. Stale/corrupt/outage and cancelled-read tests exercise safe withholding; full source preservation comparison checks all original keys and values. Production multi-user capacity, iOS/Android hardware behavior and clinical validity are not certified by local Expo/browser simulation. No Phase 09 implementation is authorized.
