# P05-F03 — Mapping adjudication

Product-owner continuation after P05-F02 engineering verification authorizes the next local synthetic feature. Formal acceptance and clinical/licensing approval remain ungranted. Existing pending formal reviews and protected registers are unchanged. Implementation policy permits gated test-only engineering; no consequential clinical write is connected.

Story: an organization administrator proposes a versioned mapping between exact controlled source and target concepts, with declared equivalence, effective interval and source provenance. An independent authorized reviewer records an explicit approval/rejection/revocation. Staff inspect mapping provenance and unresolved conflicts. No model confidence is stored or inferred because confidence use has not been approved.

Risk class C (conservative engineering classification). Main hazards: wrong equivalence, competing targets, self-approval, stale/expired codes, lost concurrent review, cross-tenant disclosure and unauthorized clinical substitution. Controls: all proposals pending, immutable pinned source/target releases, four-eyes review, optimistic version checks, append-only decisions, strict tenant/role gates, effective-date checks, explicit mapping-version lookup and fail-closed translation. Only one effective approved equivalent candidate with no pending competitors may resolve; all other candidates return needs-review without a selected target. Rejected/revoked candidates cannot translate. No clinical record is changed and no licensed content import is enabled.

Schema 46 adds immutable proposals, append-only review events, idempotency receipts and a derived state view. Source/target foreign keys pin release+concept; tenant and transition triggers enforce consistency. A review changes state via a new event, never updates a proposal. Approved mappings can be revoked; terminal rejected/revoked proposals require a new mapping version for correction. Audit/outbox and command receipts commit atomically. Migration DDL and marker are transactional. Operational rollback disables new routes and retains records; teardown is disposable-fixture only.

Permissions: terminology.read for inspection, terminology.manage for proposal, new terminology.review for organization administrators, doctors and pharmacists in the local simulation. Review authority is a software permission, not proof of a qualified clinical signoff. A proposer cannot review their own mapping even if permitted. Active account/membership, server-derived tenant/facility, local synthetic sandbox and dependency availability apply to every API and page operation.

API contract v1: GET/POST /api/terminology/mappings, POST /api/terminology/mappings/[id]/review, POST /api/terminology/translate. Cookie workforce sessions, no-store, foreign-Origin denial, bounded known-field JSON, 401/403/404/409/422/503 errors. Review includes expectedVersion and idempotencyKey; concurrent or stale review returns 409. Proposal/review outbox events carry IDs/state/version only; no patient data. No external delivery or clinical activation.

UX: registry link to mapping review, queue/all views, proposal form with exact source/target tuples and provenance, detail with immutable pins and full decision history, independent role-scoped review form, explicit translation inspector and needs-review links. Cover empty/error/loading/conflict/offline/retry and responsive accessible controls. Mobile uses the existing separately authenticated web handoff. Native editing is N/A for this administrative inspector.

Tests: persisted reopen, idempotency and concurrency, self-review and role denial, two tenants, suspended accounts, immutable proposals/events, transition sequencing, expiry, unknown/reference-only content, ambiguous and non-equivalent candidates never auto-resolved, independent approve/reject/revoke, transaction and migration failures, dependency outage/production gate, browser proposal/review/translate/conflict/accessibility/responsive checks and existing regression suites. Evidence and engineering inspection precede advancement. Formal human reviews are never simulated by test actors.
