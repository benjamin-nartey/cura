# P09-F01 — Graph and typed claims

## Intended use and scope
A clinician inspecting a synthetic patient can record a typed, explicitly unverified claim, cite currently authorized source versions, inspect its provenance, and append a revision without overwriting history. Conservative engineering risk C; qualified classification/review pending. No AI generation, diagnosis, risk assessment, medication action, billing action or clinical recommendation. No model/provider is invoked. Human author and null model metadata come from the server, not the request. No F02 ingestion, F03 sufficiency policy, F04 invalidation worker or F05 general citation drawer is started.

## Architecture decisions before code
Legacy evidence.ts serves the original chart/briefing contract and mutable legacy evidence claims; preserve it and its source hashes unchanged. Reuse readTwinSourceInventory for current source/permission/integrity resolution. Add immutable graph claim headers, revisions, citation edges and command receipts at schema 58. Sources remain authoritative. Every claim has type, patient/org/facility/owner/purpose/coverage scope, immutable version, server author, null model metadata, dates, source IDs/ledger/version/hash and evidenceState=unverified. Neither citation existence nor freshness means clinical verification. Schema rejects verified states.

Owner, facility, purpose and exact permission coverage bind visibility. Source or permission revalidation precedes every read/write; even two empty patient portfolios have different context fingerprints. Correction or disappearance withholds dependent text/edges at read time; permission coverage changes hide older context. No cached result, actor claim, client model identity or external source URL grants authority. GET and bounded JSON POST use existing live Foundation-backed browser cookie/origin/session checks. The native chart opens this independently authorized web workspace without placing bearer credentials in the URL. POST supports scoped idempotency and expected-version concurrency; conflict must not overwrite or queue. Append a PHI-safe outbox event and audit atomically; a failed transaction leaves no header/revision/receipt/event. Outage/tampering fails closed, including empty source inventories.

## UI contract
Chart-linked responsive Evidence claims workspace renders real API data, bounded source choices and all current unverified claims. Draft user text is never a clinical verification. Selected claim revisions, exact source metadata, author/model and state explanations remain explicit. Loading, empty, validation, stale, unavailable, forbidden, conflict, offline, cancel, restore and retry clear prior displayed claims and do not replay commands. A cancelled request may have committed; refresh instead of replay. All controls are keyboard accessible; dates use the existing time presenter. Source selection is explicit and no source JSON is copied into draft storage.

## Verification and operation
Synthetic fixtures reuse the established patient/encounter/sourceScenario. Test happy path, uncited claim, unsupported verified input/SQL constraints, tenant/patient/purpose/facility/owner boundaries, permission revocation, source correction, dependency outage and corrupt lineage, idempotency, stale versions, actual process concurrency, atomic outbox/receipt failure, migration 57 rollback/retry and preservation. Run full domain, types, lint, optimized build, real browser/Expo regressions and source-aware end-state refresh. Do not downgrade/delete evidence for operational rollback; remove navigation/disable this derived feature. Disposable-fixture-only rollback drops new derived tables. Retain immutable data under existing retention; no deletion rights are introduced.

Success: no unsupported claim can be represented as verified; every displayed derived claim has explicit evidence state, current authorized lineage or withheld content. Evidence/remaining items are recorded after actual execution. Formal registers are unchanged; experimental register records engineering verification only.
