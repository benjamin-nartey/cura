# ADR-0071 — Versioned current-source R4 previews

Date: 2026-11-03. Status: implemented locally; formal review pending.

ADR-0002 remains the historical contract for legacy chart endpoints. It does not cover the newer patient master, visit encounters, clinical sources and work requests. Its earlier lack of a local JDK is no longer applicable. This decision adds a separate preview boundary; it does not replace those endpoints or advertise SMART.

The domain package owns seven source mappings and their inverse. `packages/fhir/profiles` contains draft, versioned StructureDefinitions, including a source-context extension. Patient maps identity/MRN/name/birth date and inactive/merged replacement state; Encounter maps the outpatient visit status, patient and period; Condition maps the exact source coding tuple, clinical/verification state, dates and references; AllergyIntolerance preserves unknown/none-known/documented distinctions through the source coding and context; Observation maps quantity or components, effective time, issued time and status; ServiceRequest maps the untransmitted request as a proposal; MedicationRequest maps a non-executable medication draft as a proposal with dose, route and recorded frequency. Synthetic coding and unit namespaces remain synthetic URNs. There is no inferred standard equivalence, administrative gender or unit conversion.

For entered-in-error conditions, clinicalStatus and abatement are omitted together to satisfy R4 con-5/con-4; the invalidated record's original resolution date remains in context and round-trips. Active conditions with a resolution date fail closed as an inconsistent source.

Original internal IDs, tenant/facility, practitioner, recorded-by information, coded pins, original workflow states, nulls and other current row metadata survive in the source-context extension. Child history is outside this current-record contract; existing history endpoints remain authoritative. This is an explicitly bounded CuraSphere profile codec, not a general-purpose partner importer. Exact inverses are checked by regenerating the entire resource, so an unsupported field cannot silently disappear. Editable clinical values are read from the R4 fields rather than copied from context. Code tuples, unit bindings, references, mapping version and executable intent are immutable in comparison. Lifecycle execution is left to existing command workflows.

The reverse-preview API reloads and reauthorizes the source record before interpreting changes. It compares the complete baseline context to current persisted facts and rejects stale/forged context with 409. It returns proposed source differences with `applied:false` and `externalDelivery:false`. It never invokes clinical write commands. These are structural mapping proposals, not clinical validation of a dose, finding or treatment. No external sharing, import write, queue, SMART scope or provider transmission is introduced.

Resource IDs and references are SHA-256 of tenant/type/source ID, preserving valid R4 identifiers and preventing cross-tenant collision. Local sandbox, active account, facility assignment, existing resource permissions and patient registration checks apply server-side. Existing source dependency failures remain fail-closed. Same-origin requests, bounded UTF-8 JSON, depth/node limits, strict field reproduction, no-store responses, escaped UI text and PHI-free audit outcomes protect the preview boundary. No new schema or independent clinical state is needed. Only access/audit bookkeeping is written.

The pinned official validator runs locally with `-tx n/a` against actual domain-generated synthetic resources, with positive and deliberately invalid fixtures. Its reports retain warnings for missing narratives and unknown synthetic code-system definitions. This is not a terminology-server result, licensed terminology validation or clinical acceptance. CI uses the same runner and uploads original logs and OperationOutcomes. Public standards package downloads are engineering dependencies; no patient resources are submitted externally.

Rollback removes the additive workbench/API and mappings; the existing clinical database and legacy endpoints remain unchanged. The local sandbox switch can immediately close all preview operations. Formal production activation remains separate.
