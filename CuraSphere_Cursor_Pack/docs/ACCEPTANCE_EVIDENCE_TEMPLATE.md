# Feature Acceptance Evidence Template

```text
Feature ID:
Phase ID:
Feature owner and risk class:
Intended users and intended use:
Source v1.0 mapping and relevant ADR:
Inventory findings and changed files:
Schemas/migrations and rollback evidence:
API/event contracts and request/response/error examples:
UI routes, accessible screenshots and every relevant UX state:
Synthetic scenario IDs, preconditions, expected and actual oracles:
Executed test commands (copy terminal output / CI run URL):
Unit/integration/contract/E2E/accessibility/load tests:
Auth/tenant/facility/purpose/consent/audit evidence:
Clinical and AI safety review and evidence (if applicable):
Observability/alert/runbook/degraded-mode and rollback evidence:
Reviewed approvals (named human, actual date and immutable review link):
Residual risks, blockers and decisions:
FINAL STATUS: ACCEPTED | BLOCKED
```

Status cannot be ACCEPTED if a mandatory item lacks evidence or required human review is pending. Phase-level acceptance must include proof of EVERY original exit criterion. Never claim automated test pass unless test was actually run.
